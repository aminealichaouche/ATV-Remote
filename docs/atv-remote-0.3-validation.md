# ATV Remote 0.3 validation

Version 0.3.0, build 3, keeps the app bundle identifier `local.roomremote.ios`, Keychain service, registry paths, protocol controller identities, and version-1 `.roomremote` format. Only the visible app name changes to ATV Remote. Install as an update using the same sideload signing/app identity to retain setup where the signer permits it.

## Visible changes

The main screen starts with the room dropdown and adjacent gear at the top left. TV selection, connection status/actions, save-pair, rooms, TV management, transfer, and version details are in Settings. Navigation target, D-pad/touchpad, playback, volume, keyboard, Apps/Inputs, and Power remain on the remote. Touch targets are at least 44 points; a 228-point D-pad fits the 284-point content width on a 320-point phone. This geometric review is separate from a rendered-screen check.

Apps errors appear inside the Apps panel with Reload apps. App launch keeps its target and selection epoch, reports peer rejection, and prevents simultaneous duplicate launch taps. Closing an old Apps presentation cannot cancel a newer Apps or Keyboard request.

## Protocol findings and changes

The user reported that Samsung volume/navigation worked but off did not. The previous adapter sent `KEY_POWEROFF` and immediately closed its socket after write completion. [Home Assistant’s maintained Samsung integration](https://www.home-assistant.io/integrations/samsungtv/) documents `KEY_POWER` for newer TVs and names it a toggle. [samsungtvws power()](https://github.com/xchwarze/samsung-tv-ws-api/blob/master/samsungtvws/remote.py) sends a single click of that key. Version 0.3 exposes **Toggle Samsung power**, sends exactly one `KEY_POWER` click, and lets actual transport events close the session. It rejects Samsung off-only/sleep actions instead of silently replacing them with a toggle. Failed or timed-out power delivery is uncertain and asks the user to check the TV before pressing again. There is no replay, fallback toggle, or off-state network wake.

The user reported an Apple TV Apps error without the exact error text. [pyatv’s Companion documentation](https://pyatv.dev/documentation/protocols/#companion-link) describes `TVRCSessionStart` with `ProtocolVersionKey: 1.2` after `_sessionStart`; [merged upstream fix #2855](https://github.com/postlund/pyatv/pull/2855) addresses newer tvOS regressions. The original SwiftATV adapter omitted it. Version 0.3 adds this optional registration on the original connection handler before app operations. Successful or older-device unsupported registration is cached once per controller; concurrent callers share registration, and a registration timeout can be retried only by the next explicit Apps request. Only the documented older-device **No request handler** rejection or a timeout specifically for this registration is tolerated; connection loss, cancellation, authentication failures, and list/launch failures propagate.

App-list request/response wire keys already matched primary references. Additional defects were silent empty lists on missing/malformed app content and success despite NSError-style launch rejection. The new parser requires a proper app dictionary and identifiers/names, accepts a genuine empty dictionary, and recognizes NSError-style failure envelopes with `_ec`, `_ed`, `_eu`, and `_rT=8`. [pyatv issue #2868](https://github.com/postlund/pyatv/issues/2868) supplies a real FBS rejection and reports remaining firmware-specific app behavior. Registration fixes a verified omission; it does not establish that every TV or app will answer or launch.
