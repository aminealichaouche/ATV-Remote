# ATV Remote 0.3.28 selective setup transfer

Version 0.3.28, build 31, replaces the long sharing form with compact TV checkmarks and separate **Room Group Pairings** (room/TV assignments) and **Saved TV access** (credentials) choices. Every choice is a whole-row button, so the label is tappable. Export completion shows actual TV/room/access counts, the file-send action and the separate four-word phrase. Exporting access still requires Face ID or the iPhone passcode; the new UI test declines access rather than invoking authentication or reading pairing records.

The receiver unlocks the file before seeing an import preview. It shows exact new/reused counts, incoming name/type/IP, retained local names and differing saved IPs, available shared access, wake MAC when supplied, selected TV assignments for every room, and planned room-copy names. Individual TVs and rooms can be excluded and shared access can be declined. Conflicting identities are visible and disabled. Equal IPs never merge different identities and get a review warning. A matching TV keeps the receiver's profile and access. Matching normalized room names and assignments can reuse a local room even with a different room ID; other conflicts preserve the original and create deterministic named copies. Repeated import remains idempotent. Duplicate selected incoming groups that resolve to the same new room are labeled Already included.

Complete payload validation precedes any selection filtering. Selected room slots cannot refer to excluded TVs, and excluded/declined credentials are removed and validated again. The original version-1 data fields and version-2 encrypted envelope remain; TV-only exports have an empty rooms array and require **0.3.28 or later on the receiving iPhone** because older validators required a room. Transfers containing rooms keep the prior field format. Existing phrase and legacy-code files still import. Import creates no TV control commands and never replaces existing credential records. Normal Auto room behavior can resume after leaving settings if already enabled.

Nine new selection/review/model cases plus 23 existing encrypted-file/merge cases and three recovery cases actually passed: **35 hosted iOS 27 unit tests, zero failures**. Cases cover TV-only round trip without a fake room, excluded credentials/slots, declined access, invalid excluded data still rejecting, conflict visibility/default exclusion, equal-IP identity distinction, normalized name/assignment reuse, exact copied-room preview/repeat import and empty selection rejection. The other 188 native cases were not rerun. [Unit report](../audit/reproductions/atv-remote-0.3.28-native-unit-tests.json).

All 17 UI methods compiled. Four targeted native simulator cases actually passed with zero failures: share without groups/access, receiver preview and selected import preserving its original room/name, wrong/correct four-word phrase with explicit approval, and legacy code with explicit approval. The new selected import declines synthetic shared access before committing, so no credential record is imported; no share-sheet send, TV commands, home TVs or physical AirDrop are used. Initial UI checks exposed label taps failing to toggle native switches; explicit full-row checkmark buttons replaced those controls and the final run verified both choices. Two dark-mode screen captures were exported and visually reviewed. [UI report](../audit/reproductions/atv-remote-0.3.28-ui-runtime.json), [screenshot manifest](../audit/reproductions/atv-remote-0.3.28-ui-screenshots/manifest.json). Thirteen other UI cases were not rerun. Physical AirDrop and copied access on two iPhones still need hardware testing.

The unsigned arm64 iPhoneOS archive passed. The transfer model, screen and store objects are linked in the archive, with selection/review methods verified in the arm64 object. All 12 IPA files byte-match the archive, ZIP integrity passed, and all 67 source/resource/script inputs and 55 native compile inputs remained frozen. DEBUG fixtures and tests are absent. Display name ATV Remote, bundle ID `local.roomremote.ios`, minimum iOS 27 and pairing identity remain.
