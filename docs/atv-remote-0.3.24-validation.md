# ATV Remote 0.3.24 Auto rooms and status observation

Version 0.3.24, build 27, adds Auto as the first Room menu item, with **Auto · [room]** displayed on one line at the top left. Auto is a local preference, retained across relaunches. Named rooms and explicit individual TV selections exit Auto without unnecessary reconnects. Room assignments, pairing identity, star preferences and transfer schemas remain unchanged.

Auto reuses an existing connected room. Otherwise it races saved room-assigned TVs using only existing pairings, with at most four trials at once. Shared TVs are deduplicated and ambiguity prefers the current room. Failures free a trial slot; the first authenticated success cancels new scheduling. Successful late losers are closed. The store adopts the winning actor/socket and that room's saved pair without reconnecting the winner or saving new assignments. Callback instance tokens are installed only at commit; stale canceled candidates cannot update a later manual connection. Opening a modal, manual choice, registry change or backgrounding invalidates the run. Healthy rooms remain stable; all-lost scans have a 15-second minimum backoff and run only on an idle main screen.

No trial sends wake/power/HID actions, requests new pairing/trust, or tries an unassigned TV. Apple saved-only connections reject missing credentials before discovery/controller-identity creation. Samsung trials require both the saved token and certificate pin, and hold newly returned tokens in memory. A winning handoff can refresh only still-existing original matching token/certificate records through a non-suspending Keychain actor transaction; changed/deleted records cannot be recreated. Losing trials do not write pairing records. Trial cleanup may have to finish before handoff; no live TV scan-speed result is claimed.

Driver events still update status immediately. A cancellable foreground task reads established selected transport state every two seconds, guards its request/target/epoch, and downgrades stale green indicators. It does not replace pending/error details or manufacture authentication, and sends no app-list, power, ping or HID request. The task stops on backgrounding and does not reconnect healthy sessions. Two seconds is a polling interval, not a guaranteed detection deadline for a silent network/peer loss. [Apple connection-state documentation](https://developer.apple.com/documentation/network/nwconnection/stateupdatehandler), [primary transport-loss limitations](https://pyatv.dev/support/faq/).

Auto means the first reachable authenticated room, not physical proximity. Several reachable rooms can produce different winners; sleeping Apple TVs may still accept a Companion connection. The current room is held while either paired session remains connected. Physical multi-TV selection, standby behavior and long-sleep network loss still require testing on the user's devices.

All 206 hosted iOS 27 unit tests passed with zero failures against the frozen inputs. Thirteen new Auto model/race cases cover assigned-only candidates, shared-TV deduplication/current-room preference, manual-disconnect exclusion, invalid slots, connected-room mapping, status downgrades, bounded scheduling, first success, late loser disposal and canceled/empty/all-failed runs. Four native Keychain cases use randomly named synthetic records and remove them: matching refresh, changed-record rejection, forgotten-record non-recreation and exactly one winner between concurrent refreshes. No user credential keys are read or changed. Native build-for-testing passed with 52 frozen native inputs and all 15 UI methods compiled. Four targeted simulator UI checks actually passed with zero failures: Auto first-menu position, title, persisted mode and manual exit without resetting healthy indicators; observed loss reflected by the periodic poll while the other TV stays connected; the existing background/return retention case; and distinct Home tap/double/hold dispatch. Auto UI uses the existing synthetic established-session fixture; bounded first-success/loser cleanup is tested independently by the production generic race runner. Status UI changes a synthetic observed connection flag through a DEBUG-only control, then waits for the actual two-second foreground poll to update the indicator. It does not test real network loss timing. Eleven other UI methods were not rerun.
