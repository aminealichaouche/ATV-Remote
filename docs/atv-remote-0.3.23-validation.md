# ATV Remote 0.3.23 retains established TV sessions

Version 0.3.23, build 26, removes the deliberate disconnect of both selected TVs during backgrounding. Established outbound sessions and their callback epochs stay intact. Returning to the app does not restart a connected session. The automatic-connect policy accepts only disconnected/failed selected targets that were not explicitly disconnected, preventing duplicate connection attempts for established or pending states. An explicit retry still replaces an unresponsive session deliberately.

Backgrounding still cancels unfinished controls, restart workflows, discovery, setup and temporary presentations. Original command request IDs are invalidated; closed app/tool/transfer views reject their late results. Pending connection/setup states are stopped. Already-started Apple button sequences can finish their existing key-up on the original handler; canceled UI request IDs discard results. No new driver cancellation propagation is added, because stopping between key-down and key-up could leave a button held on a retained socket. Restart workflows remain directly cancellable between their checked steps. A canceled shortcut may perform only original-touch release, never repeat its swipe or resume. An uncertain in-flight Samsung write retains its existing connection-reset policy. No credentials, room assignments, preference schemas, vendor code or background entitlements change.

This preserves sessions during ordinary app switching; it cannot promise a live socket after force-quit, system termination, network change or peer closure. [Apple documents background suspension and system termination](https://developer.apple.com/documentation/uikit/preparing-your-ui-to-run-in-the-background) and [the process lifecycle](https://developer.apple.com/documentation/uikit/managing-your-app-s-life-cycle). Cold launch starts new connections with the saved pairing. No foreground activity is run indefinitely in the background. A stale socket that has not reported failure retains the existing scoped timeout recovery, without action replay.

Validation uses synthetic UI identities and offline unit policies; no live TV commands are sent. All 189 hosted iOS 27 unit tests passed with zero failures, including four new policy cases: activation preserves established/pending sessions, disconnected/failed targets can reconnect, backgrounding preserves only established sessions, and failures cannot undo a manual Disconnect. Existing command ownership, restart cancellation, pairing, room and transfer tests also pass.
