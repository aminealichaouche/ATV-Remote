# ATV Remote 0.3.31 restart shortcut reliability

Version 0.3.31, build 34, addresses the reported partial close and missing relaunch. The shortcut waits two seconds after opening the exact installed app, one second after opening the app switcher, then sends one full-height upward flick. Six hold frames replace twelve, with 112 ms of planned waits instead of 208 ms; validation and transport add elapsed time. It waits 1.2 seconds after release and directly launches the same bundle ID. The intermediate Back request is removed: previously, its failure aborted the sequence before relaunch even if the card had already closed. This is a code-level failure path, not a confirmed diagnosis of the user's second attempt. Gesture/timing changes are tuning and require physical Apple TV testing.

App open, switcher, close gesture and relaunch failures carry a stage label and the original error. Bottom diagnostics remain below the shortcut buttons. Wrapped Companion HID acknowledgement timeouts retain the existing single connection refresh for future commands; the macro is never resumed or replayed. Launch timeouts do not trigger that HID recovery. Both restart shortcuts use the shared workflow; Xfinity remains one tap with no hovering confirmation. Cancellation, session/TV changes, original-touch cleanup and installed exact-bundle checks remain. A completed message means restart commands were sent, not verified process termination.

All **32 targeted native iOS 27 tests passed with zero failures**: 21 restart workflow cases, eight command-delivery/recovery cases and three Home binding cases. They cover exactly one close, direct exact relaunch, a failure on the second launch labelled Reopen app, no automatic retry, cancellation after release, session replacement during the close-animation wait, gesture cleanup, invalid/missing app IDs and wrapped timeout recovery. Protocol I/O and waits are substituted. [Native report](../audit/reproductions/atv-remote-0.3.31-native-unit-tests.json).

Two existing native simulator UI cases passed with zero failures: Home gesture suppression and success diagnostics below both shortcut buttons with app-chooser Back navigation. The shortcut UI uses its DEBUG completion fixture; it does not test physical gestures or launch delivery. The passing shortcut screenshot was exported and visually reviewed. All 19 UI methods compiled; 17 were not rerun. [UI report](../audit/reproductions/atv-remote-0.3.31-ui-runtime.json), [combined validation](../audit/reproductions/atv-remote-0.3.31-validation.json).

The unsigned arm64 iPhoneOS archive passed, all 12 IPA files byte-match it, and ZIP integrity passed. The workflow, driver, command-delivery and store objects are linked in the archive. 67 source/resource/script and 55 native compile inputs stayed frozen. DEBUG fixtures are absent. Display name ATV Remote, bundle ID `local.roomremote.ios`, minimum iOS 27, existing pairings and room preferences remain.

Research checked [Apple's force-quit instructions](https://support.apple.com/guide/tv/force-quit-an-app-atvb39f389ec/tvos) and [pyatv's Companion touch/launch implementation](https://github.com/postlund/pyatv/blob/master/pyatv/protocols/companion/api.py). These support the switcher/swipe and bundle-launch mechanisms; they do not establish a tvOS quit threshold, card-focus acknowledgement or guarantee that this timing works on the user's hardware.
