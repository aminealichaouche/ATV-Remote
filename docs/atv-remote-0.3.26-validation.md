# ATV Remote 0.3.26 connection observation after off

Version 0.3.26, build 29, schedules one read-only observation of the captured TV connection after a one-second delay when attempting Apple TV Off (sleep/powerOff) or Samsung Off (powerToggle). The delay starts immediately before the command attempt awaits its driver send; it does not wait for a potentially slow acknowledgement. It can still check after uncertain command delivery, without resending power. Wake and ordinary buttons do not schedule this check.

Driver callbacks still update immediately, and the regular foreground status monitor still runs every two seconds. The extra observation sends no ping, HID, wake, discovery, reconnect or retry. A closed transport downgrades an otherwise connected dot to gray; a standby TV whose remote session remains connected stays green. Error/pending state is preserved. Connection is not proof that the display is on, and a locally ready transport is not a guarantee of an immediately detected silent network failure. The one-second delay is an observation schedule, not a physical-TV shutdown/detection guarantee.

Both sides of the awaited observation are protected by the selected device ID, selection epoch, driver callback instance, foreground lifecycle request, per-kind check request and task cancellation. Selection changes, reconnections, manual disconnects and backgrounding cancel the check. Another off attempt supersedes only the same kind's previous check. It does not hold the command slot while waiting or call Auto room selection; normal existing Auto behavior remains separate.

Eight new native cases exercise target-only loss, a live standby session staying green, error preservation, selection/session changes before and during an asynchronous observation, background cancellation including a wait that ignores cancellation, and cancelled sleeps. Together with seven existing command-delivery cases and thirteen Auto/status/race cases, all **28 targeted hosted iOS 27 unit tests passed with zero failures**. The other 186 native cases were not rerun. All 15 existing UI methods compiled; no UI cases were executed for this state-only change. No physical TV commands or live Wi-Fi standby behavior were tested.
