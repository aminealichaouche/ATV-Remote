# Apple TV Companion button timeouts

Reviewed 2026-10-12. `Operation timeout: companion request_hidC 5.0s` means a Companion HID button request did not receive its matching reply before this app’s five-second runtime deadline. It does not establish whether the TV received or acted on the press. The app uses TCP over the home network, not a direct phone-to-TV Bluetooth link. Distance-related Wi-Fi trouble is a plausible explanation from the user’s report, not a measured cause.

The native adapter already serializes button commands and the app reserves one command slot per TV. Companion sends request/response HID down/up messages, matching [pyatv’s primary implementation](https://github.com/postlund/pyatv/blob/master/pyatv/protocols/companion/api.py). Changing them into unacknowledged events or automatically repeating a timed-out press would obscure delivery or risk duplicate actions. Increasing the timeout alone would delay reporting a genuinely stalled session; this update retains the existing deadline.

Version 0.3.21 refreshes the selected Apple TV connection once after a scoped Companion `_hidC` request timeout on a normal control action. The action is never repeated. Existing connection epochs/cancellation and selected-device checks still gate recovery. Sleep/power-off, Samsung commands, canceled/stale commands, other protocols, app-list timeouts and authentication errors do not trigger this recovery. A fresh connection failure stops with its normal failure state; there is no automatic connection retry loop. Existing pairing keys, TV selections and rooms remain.

The same timeout during Xfinity preparation/card navigation/finish releases the shortcut reservation, refreshes the connection and leaves the shortcut failed. It never resumes the workflow or replays a swipe/press; the user must begin a new workflow after reconnecting.

For the user’s distance-related symptom, try nearer the Wi-Fi router/access point and compare Apple’s Control Center remote from the same location. Problems in both would support a network explanation; only this app failing would narrow investigation to our connection handling. [Apple’s interference guidance](https://support.apple.com/en-us/102319) recommends moving a Wi-Fi device closer to its router. [Apple’s TV Wi-Fi guidance](https://support.apple.com/en-us/102346) covers obstructions and using Ethernet if the TV has a port. [Apple’s iPhone Remote setup](https://support.apple.com/en-us/108778) requires the same home network. No Wi-Fi measurements, live-TV commands or changes to the user’s router were performed.
