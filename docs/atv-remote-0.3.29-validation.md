# ATV Remote 0.3.29 immediate saved-MAC use

Version 0.3.29, build 32, tightens the Save-to-On path. Save ends editing, validates/canonicalizes the MAC, persists the nonsecret registry atomically and updates the preferences mirror/live registry before closing the editor. Re-saving an unchanged address also persists and releases this selected TV's pending wake ownership/feedback. The editor seeds its draft once rather than reloading on appearance after scanning. An empty Save is rejected; explicit Remove saved MAC clears the record and draft.

Power On reads the current saved Samsung profile at tap time rather than relying on the row's captured MAC. The displayed device ID must still match the selection. The actual immutable wake target is built from that live record. Canceled wake command tasks are retained in a cleanup chain; the next request awaits their completion before using the shared sender actor, then rechecks ownership, epoch, current endpoint and cancellation. This closes a window where UI cancellation releases the slot before the previous sender has finished cleanup. Saving does not itself send a wake packet, change rooms/pairing keys or disconnect the awake remote session. The sender/network protocol, unicast port and packet format were not modified.

The existing code already wrote changed MACs synchronously; this is runtime/editor hardening, not a claim that the user's physical symptom was reproduced. A packet already submitted cannot be recalled. UDP request submission does not acknowledge that a Samsung woke. Network reachability, active-interface MAC, standby behavior and actual Wi-Fi wake still require testing on the user's TV.

All **62 targeted hosted iOS 27 native tests passed with zero failures**: fourteen wake packet/normalization/target/gate/cancellation and subnet cases, 45 registry/room/identity/per-TV cases, and three storage/recovery cases. Other 161 native cases were not rerun. [Native report](../audit/reproductions/atv-remote-0.3.29-native-unit-tests.json).

All 19 UI methods compiled. Two new native simulator UI cases actually passed with zero failures. The first enters a new MAC, presses Save and immediately On, applies a different MAC through manual scanner review, saves and presses On, re-saves the unchanged value and presses On again, terminates/relaunches without reseeding the registry and verifies the persisted value, then checks the other TV's MAC stayed unchanged. Each On attempt has a separate recorder count and checks device ID, IP, canonical MAC and 102-byte production packet. The second proves blank Save does not erase an existing MAC and explicit removal routes On back to setup. A DEBUG recorder replaces UDP transmission, and automatic connections are suppressed for synthetic profiles. No TV socket, wake packet or user credential is accessed. The passing screenshot was exported and visually reviewed. Seventeen other UI cases were not rerun. The cleanup-chain path was reviewed; real network cancellation timing was not injected in these UI cases.
