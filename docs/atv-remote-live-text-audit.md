# ATV Remote live camera text review

Reviewed 2026-10-12 for version 0.3.13, build 16. This review covers the live scanner, text parser, and Samsung setup integration. It is a source review with parser execution and native compilation; it does not establish camera performance or TV compatibility on hardware.

The app reads visible TV text through VisionKit’s `DataScannerViewController`, configured for text recognition only. The controls beside the Samsung IP and MAC fields have 44-point touch targets and accessible labels. Both open the same live scanner. Pointing the camera at Network Status or About This TV collects labeled address candidates; **Review addresses** removes the camera controller and opens editable fields. It does not take a photo, offer a photo-library picker, decode QR codes, or upload scan contents. [Apple’s camera text scanning documentation](https://developer.apple.com/documentation/visionkit/scanning-data-with-the-camera) describes the framework’s live-video text recognition and availability checks.

Camera access is requested only after the scan control is opened, with an explicit usage description. Support, authorization, and availability are checked before mounting the scanner. Denied, restricted, unsupported, and temporary failure paths offer manual entry. The code uses the documented main-actor scanner and delegate APIs, also checked against the local Xcode 27.0 / iPhoneOS 27.0 Swift interface. [DataScannerViewController](https://developer.apple.com/documentation/visionkit/datascannerviewcontroller) documents these prerequisites.

The following issues were identified and corrected during review:

- A canceled permission task could have reached the system permission request before checking its generation. Cancellation, view visibility, and generation checks now precede authorization work.
- The system camera permission alert can make the app inactive. Treating that as background cancellation would discard the first-use request. The request now survives this inactive state; if its answer arrives before the app becomes active, scanning resumes from the authorization status after activation. Backgrounding still invalidates the session and clears temporary text.
- Stopping recognition alone can leave the camera’s live video visible. Review, cancellation, background, and failure remove the representable. Dismantling cancels startup, clears the delegate, and stops scanning; the asynchronous startup task holds the scanner weakly. Apple explicitly permits starting and stopping recognition while live video remains displayed, so controller removal matters. [Scanning data with the camera](https://developer.apple.com/documentation/visionkit/scanning-data-with-the-camera), [stopScanning](https://developer.apple.com/documentation/visionkit/datascannerviewcontroller/stopscanning()).
- A URL such as `https://example.com/?ip=192.168.1.50` exposed an inner `ip=` label after the URL prefix was split away. URL-context rows are now rejected before label segmentation. Label and address-token boundaries reject URL path/query delimiters; regression cases include nested queries, paths, scheme-less domain queries, MAC queries, and Unicode prefixes.
- Compound labels such as Bluetooth Device MAC Address, Remote Device MAC Address, and Smart Control MAC Address could expose a generic inner MAC label. These specific forms are now excluded and tested.

Every parse uses text from one complete current scanner frame. Geometry joins pieces from the same physical row; labels are never retained from an older frame. A label may claim a value on its own row or the immediately following row only. Frame processing and parsing are bounded to 200 items/rows and 20KB of text; parser rows longer than 400 characters are rejected rather than truncated into a valid address. Accumulation keeps at most eight IP candidates and eight MAC candidates. These source limits prevent unbounded candidate growth, but geometrically inferred row association still needs checking against real TV screens.

Addresses require recognized network labels. The parser reuses the existing strict private IPv4 and unicast MAC validators. It does not replace unclear OCR characters with guessed digits. Gateway, DNS, subnet, public/external IP, Bluetooth, remote/controller, serial, and pairing labels are excluded in the implemented forms and regression cases. This is a conservative set of supported labels, not an exhaustive classifier for every TV’s wording or language. Model codes are bounded and ambiguity is retained rather than selecting one; setup does not automatically rename the TV from a scanned model.

Wi-Fi and Ethernet MAC candidates remain distinct. If multiple addresses are detected, the review fields stay unselected until the user chooses or edits them. The app cannot infer which adapter is currently active. A MAC-only scan is supported when About This TV does not display an IP; it cannot discover an address absent from the visible text.

For a new Samsung TV, **Use these addresses** fills only the setup drafts. The user still chooses a name and presses **Add and pair Samsung TV**. For a saved TV, **Use MAC for [TV name]** fills only its MAC draft; the existing **Save** action remains separate. A scanned IP that differs from the saved destination is blocked in the review and checked again in the destination callback. Scan acceptance itself does not pair a TV, write the registry or Keychain, change a room, or send a TV command. Visible text is not proof of device identity; pairing keeps its existing trust checks.

All 16 actual-source parser XCTest methods passed with zero failures after the fixes. The log is [atv-remote-0.3.13-parser-tests.log](../audit/reproductions/atv-remote-0.3.13-parser-tests.log). The native app, unit target, and eight UI methods compiled successfully. The new UI method uses a DEBUG-only text fixture to check adapter selection and draft-only filling; it was compiled, not executed. The fixture does not mount a camera or request permission and is excluded from release builds. [Native compilation evidence](../audit/reproductions/atv-remote-0.3.13-ui-compile.json).

No actual camera, iPhone, TV, photo library, local-network endpoint, or pairing Keychain was accessed for this review. Glare, TV fonts, recognition accuracy, geometry, and the physical camera indicator’s teardown timing remain unverified. Manual correction and entry remain available. Source hashes and the reviewed invariants are recorded in [live-text-audit.json](../audit/reproductions/atv-remote-0.3.13-live-text-audit.json).
